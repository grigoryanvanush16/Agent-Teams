# File Organizer — дизайн

**Дата:** 2026-06-18
**Статус:** дизайн утверждён, переход к плану реализации

## Проблема

Файлы стекаются на ПК из четырёх источников: я (Claude) генерирую `.py/.json/.txt` в рабочем корне, пользователь скачивает из веба, получает от коллег через Telegram, Я.Мессенджер и почту. Всё оседает в `Downloads` и рядом, перемешивается, теряется. Существующий `sort_artifacts.py` матчит только префиксы (`fp_`, `direct_`, `tmp_`) и разбирает лишь `.claude/.claude/` — реальные файлы с человеческими именами («Отчётность КК.xlsx», «статусы_Февраль 2026.xlsx») под него не попадают.

## Цель

Помощник, который автоматически и осмысленно раскладывает входящие файлы по существующим папкам проектов, ничего не теряя и не затирая, и со временем учится на подтверждениях пользователя.

## Решение: два слоя над одним манифестом (подход «гибрид»)

### Наблюдаемые источники
- `~/Downloads` — только верхний уровень
- `~/Downloads/Telegram Desktop` — вложения из Telegram
- Я.Мессенджер — папка сохранения (на этапе реализации проверить настройку приложения; по умолчанию `~/Downloads`)
- `~/.claude/.claude` — рабочий корень
- `~/Desktop` — только верхний уровень

### Слой 1 — `file_router.py` (быстрый, детерминированный)
- Запуск Task Scheduler'ом каждые 15 минут (в фазе 2).
- По каждому новому файлу — regex-матч ключевых слов из манифеста по имени файла, регистронезависимо. Первое совпадение в порядке манифеста выигрывает (порядок = приоритет: узкие правила выше широких).
- Совпало → перенос в `dest` проекта + запись в журнал.
- Не совпало → перенос в `_не_разобрано/`.
- Бесплатно, мгновенно, прозрачно.

### Слой 2 — дневной Claude-проход (`claude -p`, headless)
- Раз в день смотрит **только** `_не_разобрано/`.
- Понимает смысл файла (имя + при необходимости заглянуть внутрь), раскладывает остаток.
- По-настоящему спорное оставляет в `_не_разобрано/` с пометкой почему.
- Дописывает новые ключевые слова в манифест → слой 1 со временем ловит больше сам, токены тратятся реже.
- Пишет короткий дневной отчёт.

### Поток одного файла
```
новый файл → [слой 1: regex по манифесту]
   ├─ совпало    → папка проекта + журнал
   └─ не совпало → _не_разобрано/
                     └─ [слой 2, раз в день] → понимаем → переносим
                                                         + дописываем правило в манифест
```

## Манифест `projects.yaml`

Единственный источник правды для обоих слоёв. Стартовый манифест собирается из реального содержимого `Downloads`, а не из абстракций.

```yaml
- name: renewals
  dest: "C:/Users/User/Desktop/МД/Продления/"
  keywords: ["продлени", "renewal", "сравнен.*продл"]

- name: marketing_analytics
  dest: "C:/Users/User/Desktop/МД/Аналитика/"
  keywords: ["метрик.*маркет", "маркет.*метрик", "глоссарий метрик", "список метрик"]

- name: tz_dwh
  dest: "C:/Users/User/Desktop/МД/3.ТЗ_DWH/"
  keywords: ["^тз ", "техническое задание", "^тз_"]

- name: callanalytics_sales
  dest: "C:/Users/User/Desktop/МД/Диагностика функций/"
  keywords: ["статусы_", "квалификатор", "оператор", "operations .*\\.csv", "исходящ.*лини"]

- name: sales_reports
  dest: "C:/Users/User/Desktop/МД/КД/"
  keywords: ["отчёт продажи", "выгрузка по продажам", "выгрузка по .*лид", "план_мп", "план_лиды"]
```

(Перечень проектов и точные `dest` уточняются при сборке стартового манифеста; реальные папки в `Desktop/МД/` и `Projects/`.)

## Что НЕ трогаем
- `.md` — остаются под правилом CLAUDE.md (Obsidian/AI_Hub), инструмент их не двигает.
- `README.md`, `CLAUDE.md`, `settings*`, `.mcp*`, `.git*`, `.gitkeep`.
- Файлы, изменённые менее 2 минут назад (ещё качаются).
- Залоченные/открытые файлы (Excel/Word держат файл) — пропускаем до следующего прохода.
- Удалений нет в принципе — только `move`.

## Безопасность, журнал, откат
- **Журнал**: каждое перемещение → `~/.claude/file-organizer/journal.jsonl`
  ```json
  {"ts":"2026-06-18T10:30:00","layer":1,"src":"...","dst":"...","rule":"callanalytics_sales"}
  ```
- **Откат**: `--undo` возвращает последний прогон; `--undo-since YYYY-MM-DD` — за период.
- **Без перезаписи**: коллизия имени → суффикс ` (2)`, ` (3)`. Существующее не затираем.
- **Без потерь**: не сматчилось → `_не_разобрано/`, не «непонятно где».

### Режимы запуска
- `--dry-run` — таблица «файл → куда → правило», ничего не двигает (первый прогон всегда так).
- обычный — двигает + пишет журнал.
- `--undo` / `--undo-since` — откат.

## Фаза обучения

**Фаза 1 — Обучение (первые ~2 недели или пока манифест не покроет потоки).**
Task Scheduler не включаем. Работаем интерактивно: пользователь говорит «разбери входящие» (или я в начале сессии), я показываю таблицу предложений с уверенностью. Уверенные двигаю сразу, по спорным **спрашиваю**. Каждое решение пользователя → правило в `projects.yaml`. Манифест растёт на реальных подтверждениях.

**Переход к фазе 2.** Когда доля «спросил/не разобрал» за прогон стабильно низкая — предлагаю включить авто. После подтверждения ставлю задачу в Task Scheduler.

**Фаза 2 — Авто.**
- Слой 1 — Task Scheduler каждые 15 мин, тихо двигает уверенные.
- Слой 2 — раз в день разгребает `_не_разобрано/`. По-настоящему спорное оставляет с пометкой; в ближайшей сессии я про это спрашиваю. Мягкий канал «спросить» остаётся навсегда.

## Размещение инструмента
`~/.claude/file-organizer/` — скрипт, манифест, журнал, дневные отчёты слоя 2. В git не коммитим (личные пути) — добавить в `.gitignore`.

## Тестирование (до любого реального запуска)
- `--dry-run` на текущем `Downloads` — таблицу сверяем глазами.
- Мини-набор тест-кейсов: реальные имена файлов → ожидаемая папка; прогон после каждой правки манифеста.
- Первый боевой прогон с журналом, сразу проверяем `--undo`.

## Компоненты (границы)
| Компонент | Что делает | Зависит от |
|-----------|-----------|-----------|
| `projects.yaml` | правила маршрутизации | — |
| `router/match.py` | имя файла → проект (regex) | `projects.yaml` |
| `router/move.py` | безопасный move, коллизии, журнал | journal.jsonl |
| `file_router.py` | CLI: scan источников, dry-run, undo | match, move |
| слой 2 (промпт + `claude -p`) | разбор `_не_разобрано/`, дозапись правил, отчёт | `projects.yaml`, match |
| задачи Task Scheduler | расписание фазы 2 | file_router.py, слой 2 |

## Вне рамок (YAGNI)
- Чтение содержимого файлов слоем 1 (только имена).
- Маршрутизация `.md` (остаётся под CLAUDE.md).
- GUI — всё через CLI и сессию с Claude.
