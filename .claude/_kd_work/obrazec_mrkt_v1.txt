Маркетинг метрики v1 (формат v58) — Каталог метрик
Все метрики маркетинга, структурированы по этапам сквозной воронки (раздел I), плюс юнит-экономика (II), качество базы и сегментация (III) и отчётность (IV). Цвет «Готовности»: зелёный - считаем сейчас; жёлтый - после новой витрины; синий - проверить готовое в ClickHouse Кирилла; серый - нет данных (блокер). «Реализация в DWH»: авто в DWH / пересобрать / BI-сторона.

CTE — бизнес-правила и сборка ядра воронки
Логика сборки маркетинговой воронки: правила связки лид→qLead→оплата→выручка и полный SQL ядра dm_marketing_funnel.
-- Бизнес-правила сборки маркетинговой воронки (аналог листа CTE в ИБ метрики v58) / -- / -- 1. ЕДИНЫЙ КЛЮЧ. Лид → преобразование → оплата связываются по registration_history_id (owox). / --    Через него же выручка из backoffice.sales_report_row привязывается к каналу/лиду. / -- 2. ЛИД. Регистрация на сайте (owox.lead_registration_history / lead_info_aggregate), / --    фильтр is_deleted = false. Гранулярность факта - дата регистрации лида. / -- 3. КВАЛ-ЛИД (qLead). Факт преобразования owox.conversion_lead (conversion_date IS NOT NULL). / --    Альтернативный/сверочный признак - backoffice.lead_load_info.is_qualified = 1. Оба сверить. / -- 4. ОПЛАТА. owox.payment_lead → JOIN backoffice.sales_report_row. Тип: is_one_time=1 → разовая, иначе тариф. / -- 5. ВЫРУЧКА = payment_sum (реально оплачено = full_sum − скидки), НЕ прейскурант (full_sum). / -- 6. РАСХОД = выгрузка рекламных кабинетов (stg_ad_spend) по каналу/кампании/дате. / -- 7. ВИЗИТЫ = stg_metrika_visits (после переноса из API Метрики в БД, MP-12608). / -- 8. АТРИБУЦИЯ - last-click: канал/кампания берутся из utm в момент регистрации лида. / -- 9. ЛИДГЕН vs ОРГАНИКА - по dim_channel.is_paid (платные каналы привлечения vs остальное). / -- 10. ЭКОНОМИКА (расчётные поля на агрегатах): CPL=spend/leads, qCPL=spend/qleads, / --     CAC=spend/sales_tariff, CR_lead=leads/visits, CR_qlead=qleads/leads, / --     CR_sale=sales_tariff/qleads, ДРР=spend/revenue, ROMI=(revenue−spend)/spend.
Полная сборка dm_marketing_funnel:
DROP TABLE IF EXISTS dm_marketing_funnel; /  / WITH leads AS (                       -- лиды с атрибуцией канала и продукта (last-click) /   SELECT l.registration_history_id, l.firm_id, /          CAST(l.registration_date AS date) AS date, /          l.source_channel_group, l.source_channel, /          l.registration_product AS product, /          l.utm_source, l.utm_campaign /   FROM owox.lead_info_aggregate l /   WHERE l.is_deleted = false / ), / qual AS (                             -- преобразование (квал-лид) по registration_history_id /   SELECT DISTINCT registration_history_id /   FROM owox.conversion_lead /   -- сверить с backoffice.lead_load_info.is_qualified = 1 / ), / pays AS (                             -- оплаты, привязанные к лиду, с типом продажи /   SELECT p.registration_history_id, /          s.payment_sum, /          CASE WHEN s.is_one_time = 1 THEN 'разовая' ELSE 'тариф' END AS sale_type /   FROM owox.payment_lead p /   JOIN backoffice.sales_report_row s /     ON s.registration_history_id = p.registration_history_id / ), / spend AS (                            -- расход/показы/клики кабинетов по каналу и дате /   SELECT date, channel, /          SUM(spend) AS spend, SUM(impressions) AS impressions, SUM(clicks) AS clicks /   FROM stg_ad_spend GROUP BY date, channel / ), / vis AS (                              -- визиты Метрики по каналу и дате /   SELECT date, channel, SUM(visits) AS visits /   FROM stg_metrika_visits GROUP BY date, channel / ) / SELECT /   ld.date, /   ld.source_channel_group                                              AS channel_group, /   ld.source_channel                                                    AS channel, /   ld.product, /   COUNT(DISTINCT ld.firm_id)                                           AS leads, /   COUNT(DISTINCT q.registration_history_id)                            AS qleads, /   COUNT(DISTINCT CASE WHEN pa.sale_type = 'тариф' /                       THEN pa.registration_history_id END)             AS sales_tariff, /   SUM(CASE WHEN pa.sale_type = 'тариф' THEN pa.payment_sum END)        AS revenue_tariff, /   SUM(pa.payment_sum)                                                  AS revenue_total, /   MAX(sp.spend)                                                        AS spend, /   MAX(v.visits)                                                        AS visits / FROM leads ld / LEFT JOIN qual  q  ON q.registration_history_id  = ld.registration_history_id / LEFT JOIN pays  pa ON pa.registration_history_id = ld.registration_history_id / LEFT JOIN spend sp ON sp.date = ld.date AND sp.channel = ld.source_channel / LEFT JOIN vis   v  ON v.date  = ld.date AND v.channel  = ld.source_channel / GROUP BY ld.date, ld.source_channel_group, ld.source_channel, ld.product;

Топ-10 дашбордов для реформы
Зачем топ-10: из 14 дашбордов реестра выбраны 10 опорных - те, что несут ядро воронки и юнит-экономику и которые в первую очередь переводим на DWH.
